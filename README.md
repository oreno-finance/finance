# Finance

カード明細・口座残高・入出金・資産形成をまとめて管理する、個人向けのブラウザアプリです。HTML / CSS / TypeScriptで構成し、明細PDFと金融データはブラウザで処理します。永続データの保存先には、Microsoft OneDriveの暗号化保管庫を使用します。

## v2.0.0 — 操作性・データ整合性・安全性の改善

- ナビゲーション、年月選択、確認ダイアログ、接続状態と保存通知を整理し、PC・スマートフォンの操作を統一。
- 固定費を独立した管理画面に集約し、料金・支払条件・停止や再開の履歴と将来の変更予定を管理。開始前の契約は初期支払条件を訂正できます。
- カード還元率は利用日ごとの履歴に従って算定し、最新の未適用予定を修正・取消できます。適用済みの履歴は維持します。
- ホーム・月別サマリー・収支分析・月次レポートで収支の欠損判定を統一。明細未取得を0円とみなさず、利用なし確認は明細の登録・変更・削除に合わせて失効させます。
- Payrollの勤務先IDと本業・副業の区分を分離して扱い、実績と見込みを重複計上しません。
- OneDriveの保存競合、古い再取得結果、応答不明時の再保存、再暗号化や整理との競合を保護。既存の暗号化形式・旧データ読込互換性を維持します。
- 資産予測グラフに月の選択、表示系列の切替、キーボード操作を追加。TypeScriptの未使用宣言検査を有効化し、不要コードを整理。
- 公開前の検証には型チェック、回帰テスト、headless ChromiumによるE2E、依存関係・個人情報・秘密情報・公開物の監査を使用します。

複数端末を使用する場合は、公開後に各端末で最新版を読み込んでください。既存のOneDrive保管庫を新規作成する必要はありません。

## v1.6.9 データ競合・未保存保護

- **カード明細と分類ルールの同時編集**：同一行・同一フィールドが別端末でも編集された場合は、変更内容を比較して確認するまで上書きしません。無関係の行・フィールドは自動統合します。
- **資産の競合確認**：入出金名・日付・金額と端末側／OneDrive側の値を表示します。給与自動取得パスフレーズは画面に表示しません。
- **未保存フォームの保護**：みずほ送金予測とカード引落口座の変更状態を別々に保持し、ページの再読込やロック時の未保存警告に含めます。
- **保存結果の不確実性**：OneDriveで書込み完了した後の再取得失敗は警告として扱い、複数ファイルの部分更新などで結果が不明な場合は「結果を確認できない」と区別します。

## 主な機能

- **明細インポート**：カード会社のPDFやWeb明細を解析し、確認してからOneDriveに保存。PDF原本も暗号化して保管します。
- **明細管理**：年月別の明細検索、利用日・利用先・金額・補足などの確認と編集、原本PDFの取得。原本のダウンロード名は `YYYYMM_カード種別_明細.pdf` 形式です。
- **ルール・カテゴリー**：複数の利用先表記に共通の表示名・カテゴリーを付与。完全一致・前方一致・部分一致に対応します。
- **月別サマリー**：カード請求、定期・単発の入出金、Payrollの給与実績・見込みを集計。楽天銀行の残高推移と、引落日ごとの残高不足も確認できます。
- **口座管理**：楽天銀行・みずほ銀行・現金貯金口座・NISAの残高履歴、定期入出金、単発の入金・支出・振替・現金引出を管理します。
- **カード引落口座・みずほ送金予測**：カードごとの引落口座を指定。楽天銀行からみずほ銀行へカード代金を送金する予定を、請求額に基づき試算します。実際の送金は行いません。
- **資産予測**：現金貯金・NISA・合計の将来推移を表示。目標年齢・想定年利を変更し、積立額を変えた場合の差も試算できます。
- **Payroll連携**：別アプリPayrollの解析済み給与情報を読み込みます。Financeが給与明細PDFを直接解析する仕組みではありません。

予測や見込みは、登録した残高・予定・給与情報に基づく参考値です。銀行の実際の入出金を自動照会する機能ではありません。

## ローカルでの起動とテスト

Node.jsとnpmが必要です。プロジェクトルートで実行します。

```bash
npm ci
npm run check
npm run test
npm run verify:cloud
python3 -m http.server 5173 --directory dist
```

ブラウザで `http://localhost:5173/` を開きます。サーバーの終了は `Ctrl+C` です。`npm run test` はビルドも実行します。

## OneDriveの接続

「設定」からMicrosoftアカウントへ接続し、暗号化保管庫を作成するか既存の保管庫を解除します。Microsoft Entraのアプリ登録には、利用するサイトURLをSPAのリダイレクトURIとして登録し、必要なMicrosoft Graph権限を設定してください。ローカルでは `http://localhost:5173/` を使います。

- 金融データの正本はOneDriveにあります。`src/cloud/` に暗号化・同期・競合解決の実装があります。
- PDF原本、明細、ルール、口座設定は、それぞれ暗号化されたファイルとして保管します。
- 同じ保管庫を別端末から使う場合は、接続先とパスフレーズを一致させます。
- 旧ブラウザ保存データの移行機能は、設定の詳細操作から利用できます。

## 公開・コミット時の注意

このリポジトリはアプリの**ソースと静的配信物**を管理します。PDF原本、実際のカード明細、給与明細、銀行残高データ、認証トークン、パスフレーズ、復号鍵はGitに追加しないでください。

ビルド・テスト後は、`git diff --cached --check` とステージ対象の内容を確認してからコミットしてください。`local-data/`、`private-data/`、`.env`、PDF/CSVなどは `.gitignore` で除外します。

過去バージョンの技術的な変更記録は、Gitの履歴と既存の `README-v*.md` に保存されています。

## 安全性（v1.6.7）

保存済みのカード明細を削除する際は、明細の検算状態に関係なく確認が必要です。暗号化されたPDF原本は、明細削除後もOneDriveに保持されます。

資産・入出金の同じ項目を別端末で同時に変更すると、保存時にどちらを優先するか確認します。キャンセルすると保存せずOneDrive上の値を保護します。異なる項目は従来どおり統合されます。

HTMLにはCSPを設定し、テーマ初期化スクリプトは外部ファイル化しました。`npm run build` は `dist/` を一度削除し、古い生成物が公開されないように再生成します。

- サイドバーの「収支分析」から、直近3・6・12か月または対象年を選択できます。新しいOneDriveの保存形式は追加していません。
- 「月次」は収入・支出の推移グラフ、月別収支表、平均・最大・最小支出、カテゴリー／利用先の増減、カード・カテゴリー・利用先の月ごとの一覧を表示します。
- 「年間」は当年の経過月（過去年度は12か月）、前年の同期間との比較、カテゴリー・利用先の前年比を表示します。比較対象の明細が不完全なら前年比は表示しません。
- すべて `monthlyReport()` を読み取り専用で再利用し、集計月はカードの**支払日／引落月**で決定します。利用日への切替機能はありません。
- カード未登録月は未取得、暫定明細は暫定、問題明細・不明な確定状態は要確認と表示します。欠測は0円で補いません。カード別の未取込月も0円ではなく「未取得」として扱います。収入未取得・明細未取得の場合、算出できない収支は空欄扱いにします。
- NISA積立は資金流出に含め、生活費・カテゴリー明細からは除外します。振替は元の月別集計どおり収支計上しません。
- グラフの各月や表の金額から月別サマリーへ移動できます。月別サマリーの元データ・保存・競合・暗号化は変更していません。
- 月次レポートの暗号化保存、定期支出候補、楽天銀行グラフのタップ機能は次の開発段階です。


## v1.8.3 カード定期支出の候補

- 「定期支出」では、確定済みのカード明細を引落月（支払月）で比較し、毎月3回以上または別年2回以上のほぼ同額請求を候補表示する。暫定明細、重複請求月、NISAカード積立は除外する。
- 「登録」「今回は対象外」は確認後にのみOneDrive暗号化資産設定へ保存。取り消しも可能。カード払いの登録情報は**分析用メタデータ**であり、定期入出金（銀行引落）の予定や月次収支へ絶対に加算しない。
- 検出結果は確定した契約・将来の請求保証ではない。年払いは2年以上の履歴が必要。
- v1.8.2以前の`finance-assets-v1`はそのまま読み取り可能。新しい任意フィールドの三者比較、保存結果未確認保護を継承する。


## v1.8.4 楽天銀行グラフの明細選択（P1-D）

月別サマリー内の楽天銀行予測残高グラフで、点のタップ／クリック、または横スクロール可能な日付ボタンから日付を選択できます。
選択日の増減、日末の予測残高、カード引落・給与・送金・定期／単発入出金の内訳を表示します。
日付ボタンでは左右・上下矢印、Home、Endキーで移動できます。既存の日別一覧は折りたたみ表示として維持します。
確認済みの基準残高より前に存在しない残高を生成せず、残高不明時にはグラフを表示しません。
OneDriveへの書込み、暗号化形式、集計・残高予測の計算規則は変更していません。


## v1.9.0 分析→明細ドリルダウン（P2）

- 収支分析のカード・カテゴリー・利用先ランキングの名称、期間合計、月別金額を選択すると、該当する保存済みカード明細と取引行を明細管理で絞り込みます。カテゴリー・利用先の前月比や前年比の項目も同じフィルタへ移動します。
- 分析集計と同じ**支払日（引落月）**を基準にし、通常の明細管理の**請求月**による絞り込みは変更しません。分析経由時は専用フィルタを表示し、請求月操作を隠します。
- ホームの「未分類の取引」からも当月の未分類行を表示できます。ホームまたは収支分析へ戻るボタン、絞り込み解除を用意しました。
- 不正明細や重複明細は月別集計と同じルールで対象外にし、NISAカード積立はカテゴリー・利用先には混ぜません。未取得の月・存在しない行を0円の取引として生成しません。
- フィルタは**タブ内の一時状態のみ**。変更するのは表示対象で、明細の保存形式・OneDrive・暗号化や収支の計算は変更しません。
- 開発用の適用コマンドからブラウザ自動起動とサーバー自動起動を除きます。表示が必要なときだけ利用者自身が操作してください。
